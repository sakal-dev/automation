No VPS, no GH_TOKEN PAT to manage — it all lives inside GitHub. In integrated mode a scheduled sweep does poll SakalMaster's queue (claim_next_task, one leased task per run) and reports the run back; it authenticates by GitHub OIDC, so there is no SAKAL_TOKEN to store — just id-token: write. Trade-off: work happens only when a trigger fires (cron or @claude), so latency is your cron interval, not a live worker.
